# Соответствие заданию ЛР3

Проверены обе страницы предоставленного PDF, включая примечание,
семь вариантов предмета сравнения и восемь требований с подпунктами.

| Пункт | Реализация | Подтверждение |
|---|---|---|
| Примечание: микробенчмарки, не тяжёлые интегральные сценарии | Только операции над памятью, без API/БД/сети | `bench/codec.go`, network=none |
| Задание: два разных объекта одной задачи | Две стандартные библиотеки: JSON и gob | 12 комбинаций, одинаковые структуры |
| Рекомендация 100 нс–50 мс | Небольшие объекты, проверка всего диапазона | `outside_100ns_50ms`, min/max в summary |
| 1. Не менее 100 испытаний, статистическая оценка | 100 новых процессов на каждую комбинацию; медиана, CI, перцентили | `manifest.json`, `summary.json` |
| 2. Warmup/teardown | Отдельные начальная и заключительная серии; исключены из основного распределения | Поля фаз и счётчики raw |
| 3. Google Benchmark как пример; собственные средства допустимы | Прочитано руководство; собственный Go-harness | `harness.go`, описание методики |
| 4. Достаточно одного CPU | cpuset, quota 1 CPU, GOMAXPROCS=1 | Docker inspect в manifest и runtime в raw |
| 5. Несколько сценариев | Запись, чтение, запись+чтение; 4/64 записи | Таблицы и 6 наборов графиков |
| 6. Отдельный образ на прогон, одинаковая конфигурация | 100 уникальных image ID; label отличается, RootFS/Config проверяются | Все образы и контейнеры в manifest |
| 7. Оценить overhead, желательно 4–5 нс | Пустой пакетный цикл, 9 повторов; отдельно таймер запроса | overhead каждого испытания и отчёт |
| 8a. График величины во времени | Все индивидуальные задержки и время начала | Левая панель каждого рисунка |
| 8b. Распределение по перцентилям запросов | Quantile plot по 25 600 запросам на комбинацию | Средняя панель; число N в легенде |
| 8c. Гистограмма распределения | Все запросы, общие бины для двух кодеков | Правая панель |
| 8d. p50/p75/p90/p95/p99 | Nearest rank по отдельным задержкам | HTML, CSV, JSON |
| 8e. Время теста | Фазы, комбинация, Go-процесс, весь Docker-эксперимент | raw, manifest, HTML |
| 8f. Число операций, warmup/teardown отдельно | 4 независимых счётчика фаз, контрольные и проверочные вызовы отдельно | raw, summary, HTML |

Варианты предмета сравнения в задании — альтернативы: реализовать одновременно
ORM/SQL, разные языки, версии библиотек и индексы не требуется.
Ориентир overhead 4–5 нс указан как желательный, а не как обязательный порог:
отчёт показывает реальный результат отдельно для batch и индивидуального таймера.

Подробная методика и оговорки: [methodology.md](methodology.md).
